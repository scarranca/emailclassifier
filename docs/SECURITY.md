# Cove security review — September 22, 2026

This is an implementation review of the current local macOS app, not an independent penetration test or a claim that compromise is impossible. No cloud backend is deployed. PlanetScale is connected to development tools; the app neither connects to it nor uploads mailbox data there.

## Data boundaries and protections

| Boundary | Implemented protection | Evidence |
| --- | --- | --- |
| Mail, drafts, contacts, preferences, decisions, calendar cache on disk | Every real-account record is encrypted using CryptoKit AES-256-GCM before SQLite receives it. A fresh random nonce accompanies each write; authenticated context binds the record name and account namespace. | `RecordCipher.swift`, `Database.swift`, `EncryptedStorageTests` |
| Mailbox encryption keys | Random per-account key in macOS Keychain, device-only accessibility. Insert-only creation prevents concurrent startup from overwriting another instance's key; persisted read-back is required. Missing/corrupt/unavailable keys fail closed, without resetting mail or silently replacing a key. | `Security.swift`, `MailboxEncryptionKey.swift`, `MailboxEncryptionKeyTests` |
| Existing plaintext storage | One transaction migrates all values and a key verifier. Corrupt legacy JSON aborts the transaction. SQLite secure deletion, in-memory temporary storage, full synchronization, VACUUM and a checked truncating WAL checkpoint clean the active files. A persisted intermediate version retries interrupted cleanup before loading mail. | Migration/rollback/reopen/cleanup tests inspect main database, WAL, SHM and journal for a known plaintext marker |
| Filesystem access | Account directory 0700; database 0600; sidecar permissions tested. Non-regular database/sidecar paths are rejected; SQLite opens with NOFOLLOW after resolving parent aliases. | `Database.swift`, symlink and file-mode tests |
| API transport | HTTPS required before transmission; ephemeral URLSession with no URL cache, cookie storage, cookie acceptance or credential storage. Redirects are rejected, including 307 POST redirects. TLS uses the platform's normal certificate validation. | `HTTP.swift`, `PrivateHTTPTests` exercise actual URLSession via a synthetic URLProtocol |
| Legacy API response caches | On packaged-app startup, delete only this bundle's regenerable Caches/HTTPStorages directories before opening a mailbox. No saved attachments, account database, browser profile or credentials are removed by this cleanup. | `LegacyNetworkCache` in `Security.swift`; native verification recorded below |
| Google authorization | Desktop PKCE, random state, bounded loopback-only callback, timeout/cancellation, identity verified before atomic session replacement. Refresh credentials in Keychain; access tokens in memory; stale account generations rejected. | `Security.swift`, OAuth/session tests |
| Untrusted email HTML | Nonpersistent WebKit, message JavaScript disabled, isolated app renderer, restrictive CSP, forms/frames/scripts removed, no remote images by default. Opt-in allows HTTPS images only; no-referrer policy. | `EmailBodyView.swift`; native WebKit tests verify active-content removal and no requests to a reachable HTTP probe before/after opt-in |
| Provider errors | HTTP errors never echo response bodies or credentials. SQLite errors expose only a numeric result code. | `HTTP.swift`, `Database.swift`, HTTP error tests |
| Jev requests and actions | Bounded content and enabled preferences only; no local reply drafts in passage retrieval. Automatic processing is optional. Jev returns choices/scores/passages and cannot send mail or create events. | Jev/input-bound/automation/retrieval/workflow tests; Connections disclosure |
| Local deletion | Explicit confirmation describes loss of local drafts, contacts, events and preferences. Remove saved Google connection, invalidate in-flight state, clear UI, erase account records and compact/checkpoint. Google mail/calendar are not deleted. Ordinary Disconnect keeps the encrypted local cache. | `LocalPrivacyTests`, `EncryptedStorageTests`; native confirmation/cancel verification below |
| Executable | Stable certificate signing with Hardened Runtime; no permissive runtime entitlements added. | `scripts/build-app.sh`; strict signature/flags check below |

Synthetic sample accounts and injected test stores can use plaintext. Production account opening always supplies a Keychain key. There is no automatic plaintext fallback for a previously encrypted database.

## Optional AI providers and reading preferences (0.1.2)

OpenRouter, OpenAI API and Anthropic keys use separate Keychain items. Provider/model choices are local preferences. Writing, generated answers and natural-language Gmail query generation run only after explicit user actions; no new provider automatically processes incoming mail. Requests disclose their destination and bounded email context in the UI. Generated drafts require review and insertion, then the ordinary Send action. Providers receive no executable mail or calendar tools. Gmail search requires reviewing the query and clicking Search Gmail; it downloads at most 20 results and preserves local drafts and the sync cursor.

ChatGPT subscription support uses a separately installed official Codex app-server with separate sign-in, an isolated runtime directory, ephemeral threads, disabled tools and an outer macOS Seatbelt filesystem restriction. Tests deny reads and writes outside that runtime, including the Data-volume alias, except the explicitly selected OS keychain database and its Security.framework lock/atomic-save files needed for credential storage. Version 0.1.3 adds this bounded exception after a real login exposed the missing access; normal OS Keychain ACLs still apply. The CLI's required network access remains enabled. See [AI provider boundaries and limits](AI-PROVIDERS.md); real subscription login and generation have not been exercised with user credentials.

Reading settings can explicitly enable automatic HTTPS images. That may disclose message opens to senders; the default remains blocked. Text-only reading does not create a WebKit message view or fetch images. Native rendering tests cover switching preferences and the resulting content policy.

## Limits that remain explicit

- This is record encryption, not whole-file SQLCipher encryption. SQLite schema, record identifiers, lengths, file timestamps and the account-derived filename remain visible. Authenticated encryption detects record alteration/substitution, but does not prevent an attacker deleting data or restoring an older valid copy.
- Protection assumes the OS and running Cove process are not compromised. It does not defeat malware controlling the logged-in session, a debugger with sufficient privileges, root, screen capture, or user-approved Keychain access. Hardened Runtime is enabled; App Sandbox is not enabled. A future sandbox migration needs explicit testing of the existing database location, Keychain, OAuth loopback and user-selected attachments.
- FileVault was verified enabled on this Mac. Neither compaction nor deletion guarantees forensic erasure from SSD storage, filesystem snapshots, old backups, or copies exported before this update. Existing backups are not silently deleted. User-saved attachments remain where the user saved them.
- Losing the Keychain encryption key makes its encrypted cache unrecoverable. Gmail can be downloaded again after an explicit reset, but unsent local drafts/contacts/preferences require the original key and database. Keys are not stored beside the database or uploaded to a server.
- Disconnect removes the device's saved Google refresh credentials; it does not revoke the grant in Google's account settings. The configured TypeSafe key and Google client settings remain for reconnection. The local removal operation retains the encryption verifier/key so the cleared store can be reopened safely.
- Jev receives the selected/bounded email content when invoked, including automatic organization when enabled. TypeSafe's privacy policy says inputs are not used to train/fine-tune models, but permits retention. Zero retention has not been established. Connections now links the policy and states this limit. Do not describe Jev processing as local or end-to-end encrypted.
- Security tests cover concrete invariants; they do not substitute for independent review before distributing Cove or storing other users' mail. Cloud authentication, tenant isolation, encrypted server storage, deletion, retention, audit logs and push webhook verification remain deployment gates in the backend plan.

## Verification

- 165 automated tests passed: 123 core and 42 app/rendering tests. This includes 7 encrypted-storage, 4 key-lifecycle, 3 private-HTTP and 1 local-erasure workflow tests.
- Logs: `/tmp/cove-security-tests.log`, `/tmp/cove-security-build.log`. The final release build and strict signature check passed after formatting. FileVault was checked again and remains enabled. A targeted repository scan found no Google access-token/client-secret or private-key markers; this is not a comprehensive secret-discovery guarantee. Local environment files, SQLite caches and private-key bundle formats are excluded from Git. Strict formatting lint still flags the existing OAuth wire field names (`access_token`, `refresh_token`, `expires_in`); those style findings do not affect token decoding or the security checks.
- Native production migration completed at storage version 2, SQLite integrity check returned `ok`, all 8 current records carried the encrypted envelope, and every original record name remained. At initial migration, Inbox still showed its prior 148 messages and the existing local draft remained; subsequent normal sync received two new messages. A second launch restored the account and draft without another Keychain prompt.
- After live synchronization and restart, database/WAL/SHM were each mode 0600. A read-only scan found none of the selected known email/address/JSON-field markers. This scan establishes absence of those markers, not forensic erasure of every historical copy. The legacy bundle networking cache directories remained absent after normal sync. Evidence: `/tmp/cove-encryption-native-verification.json`; before-migration counts and record hashes: `/tmp/cove-pre-encryption-manifest.json` (no mail bodies in that manifest).
- Native Connections displayed the encryption and TypeSafe-retention disclosures. Remove local data opened the explicit destructive warning; Cancel returned to the connected account with the draft intact. Actual erasure is tested only on synthetic encrypted fixtures, including the busy-state guard and zero provider requests. No user mailbox data was intentionally deleted.
- The packaged app passed `codesign --verify --deep --strict`; CodeDirectory flags are `0x10000(runtime)` with the existing stable development signing team. Hardened Runtime and the encrypted cache worked together in the running app.
